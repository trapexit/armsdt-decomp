# Workflow templates

Use these templates to keep evidence, traceability, parity reporting, and blocker handling consistent across tools and steps.

## Templates

- [step1_evidence_log.md](step1_evidence_log.md): runtime/static evidence capture template for step 1.
- [step2_traceability_matrix.md](step2_traceability_matrix.md): requirement-to-evidence/test mapping template for step 2 specs.
- [step2_specification_scaffold.md](step2_specification_scaffold.md): full step 2 spec starting structure for `<tool>/technical_specification.md`.
- [step3_parity_summary.md](step3_parity_summary.md): three-way parity summary template for step 3 closeout.
- [blocker_closure_record.md](blocker_closure_record.md): blocker impact and closure experiment record template.

## Usage notes

1. Copy template content into the active tool artifact for the current step.
2. Keep identifiers stable and reproducible (requirement IDs, fixture IDs, evidence IDs).
3. Do not create detached scratch trackers as authoritative state.
